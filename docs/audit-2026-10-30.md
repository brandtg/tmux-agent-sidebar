## Overall read

The codebase is in unusually good shape for a solo fork: ~1,300 tests, clean clippy, no locks anywhere (one-way mpsc into a single `AppState` owner), adapters that share one hook-registration table with the setup snippets, and an audit doc that already separates verified bugs from speculation. The hook pipeline and the tmux snapshot path are the strong parts.

The weak part is the _interaction model_. The list is the only navigation surface, and every narrowing tool is coarse: six status buckets, one repo filter, and j/k. That works at 5 agents and gets painful at 15+. There is no text search, no group-level jump, no "next thing that needs me" cycle, no detail view, and no way to script the thing. So your `/` idea is not just a nice shortcut — it is the missing middle layer between "show everything" and "filter to one repo".

## 1. `/` search — where it fits and what will bite

This is a good feature and it fits the existing architecture almost cleanly. The design I'd recommend:

**State.** Keep it local to `AppState`, not in `GlobalState`. Status and repo filters are broadcast to every sidebar through tmux options; a search query must not be, or every keystroke would broadcast a refresh to all instances. A small `SearchState { query: String, active: bool }` on `AppState` is enough. No new tmux option, no persistence.

**Keys.** Intercept it before the base key map, the same way the spawn modal and repo popup already do (`handle_key_event` checks popups first and returns early). `/` opens it; printable characters append, Backspace pops, `Esc` clears and closes, `Enter` closes but keeps the query, `Ctrl-u` clears. While it is active, `q` must type a `q` rather than quit — the existing modal pattern already locks that in with tests, so follow it. Up/Down should still move the selection so you can navigate results without leaving search.

**Matching.** Case-insensitive substring over `pane.tmux_session` and `pane.session_name`, plus the group name (repo root in repo mode, session name in session mode) and branch. Matching the group name should keep the whole group visible, not just the rows whose own fields match — that is the intuitive behavior when you type a repo or session name. Window rows should match on their command/session/title fields too, otherwise `w` mode behaves inconsistently.

**The real trap: lockstep filtering.** The selection index is a position into `layout.pane_row_targets`, and the renderer's `row_index` in `ui/panes/row_collector.rs` must produce exactly the same order. Today `rebuild_row_targets` and `row_collector::collect` duplicate the status/repo filter logic and the comment there says so explicitly. A search predicate has to be applied in _both_ places, plus `status_counts` if you want the header counts to stop lying (and you do — an `all: 24` header over two visible rows is confusing). Put the predicate in one shared function in `state/filter.rs` and call it from all three sites. That is the single highest-risk part of this change.

**Selection stability.** The current clamp in `rebuild_row_targets` sends the cursor to the last row when the filtered list shrinks. For search you want: keep the selection on the same pane if it still matches, otherwise select the first match. There is already a `select_focused_context_row` helper that re-anchors by pane id; generalize that into "rebuild, then restore by pane id, else 0".

**Rendering.** Do not add a third header row. The list area and mouse mapping assume exactly two header rows (`handle_mouse_click` does `row - 2`), so a conditional extra row would desync clicks. Instead swap the content of the secondary header while search is active: ` /query▏  3 matches` on the left, repo filter button still on the right. Compute that layout in both the renderer and `handle_secondary_header_click`, or clicks will miss.

**Docs and tests.** Add rows to the `?` help popup and the keybindings doc, a state test for the match rules and selection preservation, and inline insta snapshots for the search bar and a filtered list (per the repo's UI test rule).

Two decisions worth making before I write it: substring vs. subsequence fuzzy matching (substring is predictable, fuzzy is nicer for `claude-api` → `ca`), and whether Enter keeps the filter or clears it. My default would be case-insensitive substring and Enter keeps it.

## 2. Navigation, beyond search

These are cheap and address the same scaling problem:

- A "next attention" key that jumps to the next row with `attention != None`. The Running filter already surfaces those rows, but cycling through them directly is much faster than filtering, scanning, and jumping. This is the highest-value keybinding after `/`.
- `g` / `G` for top and bottom of the list.
- `[` / `]` for previous/next group header. With repo grouping and 10 repos, scrolling to find a group is the common annoyance.
- Collapsible groups: a key on a header (or Enter when the cursor sits on a header) collapses that repo to one line. This matters more than search for people who keep many worktrees open.
- Runtime toggle for grouping (`repo` vs `session`). `@sidebar_group_by` is config-time only today, and the session mode is genuinely useful; a `s` toggle with the same broadcast pattern as `c`/`w` would make it discoverable.

I would not add vim count prefixes or half-page keys; the list is small enough that page keys cover it.

## 3. The missing detail view

Prompts and responses are truncated to previews, and the activity log is now only consumed for task counters after the Feed panel was removed (commit 5b9cc06). That is a lot of already-collected data with no UI. A pane detail popup (say `d`, or Enter on a header) showing the full prompt, last response, recent tool calls, subagent tree, ports, and git state would resurrect the one thing the audit says no competitor has, and it costs almost nothing because the data is already in `AppState`.

## 4. Structural opportunities from the audit worth keeping on the roadmap

- **Scriptability.** A `list --json` subcommand and a `wait --until idle|waiting` command that reads the existing `@pane_status` options. This turns the sidebar into something status bars and orchestration scripts can consume, and it is a small amount of code over data that already exists. It also gives you a stable test surface.
- **Hooks-optional detection.** A `capture-pane` fallback for known idle/permission patterns. This is the biggest adoption gap versus Herdr and the audit ranks it first for good reason.
- **OSC 9/777 notifications.** Desktop notifications are lost over SSH; terminal escape notifications are not.
- **Notification debounce** (re-check state after a short delay before firing).
- **Theme presets / follow-terminal.** One fixed 256-color theme is now table stakes.
- **Agent-pushed summary token** (`@pane_summary`), rendered as a muted line. Cheap, and it lets agents say "running tests" or show context percentage.
- **Resume-on-death**: capture the resume command per agent, offer respawn from the sidebar.

## 5. Correctness items still open

I checked the audit against current code. Most of the "next" items are fixed (spawn/remove is on a worker now, subagent stop is flocked, the install wizard uses tmp+mv, lsof fails open). Still open and small:

- shell-exit.sh has no `$TMUX` guard despite its header claiming it does nothing outside tmux, and the bash DEBUG trap fires for every simple command.
- install-wizard.sh still uses `pkill -f "$BINARY"`, which is an ERE, not a literal.
- `write_activity_entry` still writes `tool_name` unsanitized while sanitizing only the label.
- Codex's `SessionStart` matcher is `startup|resume`, so any other source is silently dropped.
- `is_system_message` drops any prompt containing `<task-`, which can eat a real user prompt.
- `show -g` quote round-trip is still naive for repo paths containing a double quote.

## Suggested order

1. `/` search with the shared predicate and selection preservation.
2. Next-attention cycle, group jump, `g`/`G`, collapsible groups.
3. Pane detail popup.
4. `list --json` + `wait`, then hooks-optional detection.
5. The small correctness fixes and theme presets.
