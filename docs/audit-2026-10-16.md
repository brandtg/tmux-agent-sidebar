# Codebase Audit — 2026-10-16

Full-project bug hunt and competitive gap analysis, performed after ~60 commits of
post-fork ownership. Method: baseline test/lint run, four parallel deep reviews
(hook/adapter/event pipeline; tmux integration, state, and app loop; shell scripts
and wiring; competitor research), then manual verification of every claimed
finding against the code before it was recorded here. The top findings were also
reproduced empirically against scoped (`-L`/`-S`) tmux servers, which were
cleaned up afterwards.

## Baseline health

- **Tests:** 1,314 passing (1,237 unit + UI snapshot suites), 0 failures.
- **Clippy:** clean. One false positive: `clippy::const_is_empty` on
  `EMBEDDED_PLUGIN_FILES` (`src/cli/plugin_state.rs:228`) — the constant is a
  non-empty slice of `include_str!` entries; the lint misfires on that shape.
- **Concurrency:** no `Mutex`/`RwLock` anywhere; all cross-thread data flows are
  one-way `mpsc` with the render thread as sole owner of `AppState`. No
  deadlocks possible in the reviewed scope.
- **Parsing:** all JSON paths degrade gracefully (`json_str`/`optional_str` →
  `""`/`None`); no `.unwrap()`/`expect()` on non-test paths in reviewed modules;
  `list-panes` field indexing is guarded by `MIN_FIELDS`; slicing is
  boundary-safe.
- **Injection:** every tmux/git call is an argv vector (no shell);
  `send-keys -l`; targets are tmux IDs. Verified safe against paths containing
  spaces, pipes, and quotes (`#{q:}` escaping matches tmux exactly).
- **SIGUSR1:** handler only does an `AtomicBool::store` (async-signal-safe),
  `SA_RESTART` set, flag polled via `swap`.
- **Unbounded growth:** `pane_states` pruned per tick; git-worker cache
  retained to wanted paths; activity logs capped at 210 lines hook-side; debug
  log capped at 5 MB.

Deploy parity checked: `~/.tmux/plugins/tmux-agent-sidebar` (git clone, not a
symlink) runs v0.13.0, matching this repo.

### Refuted finding: `agent-sidebar.conf:77-85` awk hook-dedup

The audit originally reported the seven `set-hook -gu` cleanup lines as dead
code, claiming the conf contained `awk "... { print \\$1 }"` (two
backslashes) which collapses in `sh` to `{ print \ }` and errors out.
**The file actually contains `\$1` (one backslash) in every commit,
including the audit base.** With a single backslash, `sh` collapses `\$`
→ a literal `$` inside the double-quoted awk program, so awk correctly
receives `{ print $1 }` and the dedup works. Ground truth: the live tmux
server (many reloads over months of development) shows exactly one hook
per event — `after-new-window[0]`, `after-select-pane[0]`, `pane-exited[0]`
— not the accumulated duplicates the bug would produce.

The reviewer's repro was built by pasting the misread two-backslash string
into `sh -c`, which does error — but that string never existed in the
conf. Lesson recorded: verify the actual bytes (byte-level, not
copy-typed) before building a repro around a quoting claim.

### 1. `src/cli/hook/activity.rs:117-122` — stale `@pane_wait_reason` survives `error → running`

`handle_activity_log` only clears attention/wait_reason when
`current_status == "waiting"`. But `on_stop_failure` sets `@pane_wait_reason`
to the error text (`src/cli/hook/handlers/run.rs:120-122`), and the renderer
shows the reason row for *any* status, changing only its color
(`src/ui/panes/row/body.rs:83-90`). So after a `StopFailure`, the next
PostToolUse flips the status to `running` while the "rate limit"/error reason
row stays on screen.

Reproduced: set `@pane_status=error`, `@pane_wait_reason=rate_limit`; dispatch
an activity-log hook with a Read payload → status becomes `running`,
wait_reason stays `rate_limit`. Control case (`waiting`) clears both,
isolating the gate.

**Fix:** clear `PANE_WAIT_REASON`/`PANE_ATTENTION` on any transition into
`running`, not just transitions out of `waiting`. (Note the OpenCode
pending-action guard at `activity.rs:111-116` — keep it.)

### 2. `src/tmux/query.rs:489-503` — one failed `ps` scan wipes a live agent's state

For Codex/OpenCode/Hermes panes whose foreground command reads as a shell,
`parse_pane_fields_with_processes` tears down all `@pane_*` options **and
deletes the activity log** when the agent process is judged dead. When the
process snapshot is `None` (`ProcessSnapshot::scan()` failure, 5s timeout
under load, `ps` missing), `agent_still_alive` is forced `false` via
`.unwrap_or(false)` and the wipe fires on a single missed observation.

The port-scan sweep already fixed this exact failure mode with
`REQUIRED_DEAD_SCANS = 2` (`src/state/refresh.rs:711`; its comment at
`:554-560` reads "a single scan can fail to see a live agent… used to delete
14 `@pane_*` options") — the parse-time sweep kept single-shot behavior.
A live agent launched under a wrapper shell (`bash -lc codex`) loses
prompt/status/activity history on any transient `ps` failure.

**Fix:** distinguish "scan failed" (`None`) from "scan says dead": pass a
missing snapshot through as *unknown, don't wipe* instead of
`.unwrap_or(false)`, or apply the same 2-strike streak used by the port scan.

### 3. `install-wizard.sh:115` — `build_from_source` copies onto the live binary → ETXTBSY *(reproduced mechanism)*

`build_from_source` does `cp target/release/tmux-agent-sidebar "$BINARY"`
*before* `post_install_fixups` (line 117) — which is where
`stop_running_instances` runs. On Linux, `cp` onto a file the sidebar TUI is
executing fails with "Text file busy" (verified in a sandbox; tmp+mv
succeeds). Since the entry script prefers `bin/`, the normal deploy is always
executing from there, so `make install` fails whenever the sidebar is running
— i.e., always, in practice. The `download_binary` path (lines 84-94) already
does the correct tmp+mv swap; `build_from_source` should kill first or use
the same swap. macOS tolerates the `cp`, which is why this never surfaced
there (only the codesign dance did).

### 4. `src/cli/hook/handlers/subagent.rs:32-40` — lost-update race in `on_subagent_stop` *(reproduced)*

`on_subagent_start` was made atomic after a prior race fix (its own comment
at `subagent.rs:16-22` describes the concurrent-hook loss), but
`on_subagent_stop` still does get → `remove_subagent` → set across
independent hook processes. Reproduced with 6 concurrent SubagentStop hooks:
9/25 rounds left the full subagent list stale. Consequences: `pane_writes_allowed`
(`src/cli/hook/context/location.rs:119-122`) stays false indefinitely,
freezing the parent's metadata, and a later parent `SessionEnd` bails at the
subagent guard (`src/cli/hook/handlers/session.rs:110`), leaving stale state
until the next `Stop` (which does clear the list, `run.rs:64`). The 2-way
case did not reproduce in 60 rounds, but the mechanism is identical to the
one the Start path's comment calls a bug.

**Fix:** give the stop path the same atomic treatment as the start path
(single tmux-level rewrite, or hook-side flock).

### 5. `src/state/popup.rs:404,462` — spawn/remove run synchronously on the UI thread

`confirm_spawn_input` calls `crate::worktree::spawn` inline, and
`pick_unique_slug` (`src/worktree/slug.rs:27-34`) does up to
`MAX_COLLISION_ATTEMPTS = 99` iterations, each calling `branch_is_free` →
`git show-ref` with a 5s timeout (`src/git.rs:14`). With a hung git (stale
NFS, blocked `index.lock` — the exact scenario `subprocess.rs` was built for)
and a taken slug, that is up to ~500 s of frozen render loop: no input,
stopped spinner. `confirm_remove` is bounded at ~15 s (3 git steps +
kill-window) — milder, same class. The codebase deliberately moved ps scans
off-thread (`src/app/workers.rs`) for exactly this reason.

**Fix:** run spawn/remove on a worker thread with results delivered via the
existing mpsc channel (and keep the popup open in a "working" state).

### 6. `src/port.rs:181` — missing `lsof` silently disables the whole process/port scan

`run_command("lsof", …)?` returns `None` for the *entire* scan when the
binary is absent or fails, so listening ports never populate **and**
dead-scan streaks never advance (`src/app.rs:244` drops `None` results) —
silently disabling liveness-based teardown for all agent types on hosts
without `lsof` (common in containers).

**Fix:** fail open — return a snapshot with empty ports and skip only the
lsof portion, so process-tree liveness (which does not need lsof) still
works.

## Likely bugs (traced, not independently reproduced)

- **`shell-exit.sh:39-85` — no "outside tmux" guard.** Neither the bash nor
  the zsh branch checks `$TMUX`/`$TMUX_PANE`, contrary to the documented
  behavior; sourced outside tmux it installs the DEBUG trap +
  `PROMPT_COMMAND` and spawns a failing `tmux set-option -p -t ""` per user
  command (silenced by `2>/dev/null` at line 23). Additionally, the DEBUG
  trap fires for *every simple command* (interactive loops/scripts cost one
  tmux spawn each) and silently replaces any pre-existing DEBUG trap (line
  58).
- **`shell-exit.sh:49-57` — `@pane_last_cmd` pollution.** The case filter
  only excludes `_tas_*`/`trap*`/empty. The user's own `PROMPT_COMMAND`
  functions (git prompts, vte integration) and the last simple command of any
  compound statement overwrite `@pane_last_cmd`, so the sidebar's
  "last command"/failed-exit pairing is frequently attributed to the wrong
  command.
- **`install-wizard.sh:58` — `pkill -f "$BINARY"` is an ERE, not a literal.**
  Regex metacharacters in the install path (`.`, `+`, `(`) are active; a `+`
  in a path widens the match, and any unrelated process whose argv contains
  the path string (editor, `tail -f`) is killed. Use `pkill -xf` or
  regex-quote the path. (Cannot match the tmux server, so it does not touch
  the hard rule in AGENTS.md — but it is fragile.)
- **`src/cli/hook/activity.rs:16-20` + `src/tmux/options.rs:232-234` —
  incomplete sanitization.** `write_activity_entry` sanitizes only `label`;
  `tool_name` is written verbatim (adapters never sanitize it). A
  `tool_name` containing `\n` or `|` splits/corrupts the `ts|tool|label`
  record and can inject fake `TaskUpdate`/`TaskCreate` entries that
  `parse_task_progress` (`src/activity.rs:161-225`) consumes into task
  counters. Also: `sanitize_option_value` replaces `\n` and `|` but not
  `\r`; a CR reaches the log where `trim_locked`'s `str::lines()`
  (`activity.rs:57`) silently strips a trailing CR on every rewrite. Low
  severity (agent-controlled payloads), but the asymmetry is real.
- **`src/tmux/options.rs:238-249` — quote-containing values round-trip
  wrong.** `tmux show -g` prints `@key "\"quoted\" value"` (verified);
  `trim_matches('"')` strips only outer quotes and never unescapes `\"`, so
  the round-tripped value no longer matches what was written and
  `rebuild_row_targets` can reset the repo filter to All. Only reachable via
  a repo directory name containing `"` — rare, but the parsing is objectively
  wrong for that input class.
- **`src/adapter/codex.rs:30` — SessionStart matcher `"startup|resume"`.** If
  Codex fires SessionStart with any other source (e.g. `compact`), the
  registered hook does not match and the event is never sent. Needs
  verification against upstream Codex behavior.
- **`src/cli/hook/context/meta.rs:52-54` — `is_system_message` over-broad.**
  Any prompt containing the substring `<task-` is silently dropped from
  `@pane_prompt`; a user literally typing `<task-list>` loses their prompt
  display. Status/attention still advance.
- **`src/adapter/claude/mod.rs:163-177` — `stop-failure` prefers
  `error_type` over `error_message`.** The desktop notification body becomes
  "Task failed: billing_error" (category) instead of the actual detail.
  Enshrined in a test, so intentional — but the detail is arguably the
  useful string.

## Competitive gap analysis — Herdr

**Identity:** herdr.dev. "The runtime coding agents run on" — an agent-aware
terminal multiplexer (tmux/Zellij *replacement*), not a dashboard app. Solo
founder (Ankara). Rust, single binary, Apache-2.0, macOS/Linux/Windows.
Repo created Mar 2026; ~44k GitHub stars, ~1.5M installs, 1,718 community
plugins at research time. Funding: YC F26 (announced Aug 2026); $6M seed led
by Bessemer with YC, e2vc, and angels (Tobi Lütke, Dane Knecht, Görkem
Yurtseven) — Oct 2026.

**Positioning:** "A runtime, not another window." A background server owns
the agents' PTYs; the TUI, CLI, SSH attach, and phone clients are all just
clients. Their pitch vs. tmux: "tmux sees panes; Herdr knows which panes are
agents and what state each is in." This is the key strategic contrast:
**Herdr asks users to abandon tmux; tmux-agent-sidebar augments it.** Their
ask is their adoption ceiling; ours is our moat.

### Gaps worth closing (terminal-appropriate, ranked)

1. **Hooks-optional agent detection.** Their biggest UX win: agents are
   detected *without hooks* by screen-scraping the pane bottom buffer
   against manifests. Our hooks are required. A `capture-pane`-based
   fallback (known permission-prompt/idle patterns) makes the sidebar work
   for agents the user never configured; a remote-manifest mechanism would
   let detection rules update without a release. **The gap that would hurt
   most.**
2. **Wait-on-state scripting.** `herdr agent wait <target> --until blocked`
   is heavily used for agent-orchestration scripts. A
   `tmux-agent-sidebar wait <pane-id> --until idle|waiting` reading
   `@pane_status` is cheap and makes the sidebar programmable the same way.
3. **Latched "done, unseen" state.** `done` stays visible until the pane is
   focused, per client. Our statuses are instantaneous; a latched completion
   badge survives the "glanced away at the wrong moment" problem.
4. **`agent explain`-style debuggability.** Per-pane introspection of *why*
   a state was assigned (matched rule, evidence, fallback reason). We have
   `TMUX_AGENT_SIDEBAR_DEBUG=1`, but not user-facing "why does this row say
   waiting?" in the popup.
5. **Agent-pushed summary token.** A short display-only string in the row
   (context %, current file, "running tests") set via hook. We have
   statuses; a free-text summary column is cheap and high-value.
6. **Resume-on-death.** Capture each agent's resume command via hooks and
   offer "respawn agent in this pane" from the sidebar (extends the
   existing spawn flow).
7. **Terminal-escape notifications (OSC 9/777).** Desktop notifications die
   on remote tmux; escape sequences land in the *local* terminal
   (Ghostty/iTerm2/Kitty/WezTerm). Cheap to add alongside the existing
   desktop-notify path.
8. **Notification debounce.** Re-verify state after `delay_seconds` before
   notifying; kills stale alerts from transient states.
9. **Theme system.** One fixed 256-color theme vs. 18+ built-ins with auto
   light/dark. Table stakes now.
10. **Configurable sidebar row tokens.** Let users define row layouts from a
    token set.
11. **Packaged SKILL.md for agents.** Teach agents to query the pane options
    (`tmux show-options -p @pane_status`). We are close already; packaging
    it is cheap.

### Not applicable (server/mobile/infra-only)

Herdr Cloud (no-SSH machine brokering), multi-host SSH federation,
server-owned PTY persistence / live handoff (that is the multiplexer itself —
tmux already provides this, which is the whole bet), phone/PWA clients,
1,700-plugin marketplace scale, Windows/ConPTY.

### Where tmux-agent-sidebar is already ahead

- **No migration.** Sessions, scripts, keybindings, muscle memory, and SSH
  setups stay. Public discussion explicitly asks for "agent status without
  leaving tmux."
- **PR numbers via `gh`.** Herdr's core sidebar shows only branch +
  ahead/behind; no PR display found in their core.
- **Per-pane tool-call activity log.** No equivalent feed in their core;
  their plugin ecosystem focuses on diff review. Genuinely differentiated.
- **Attention rings, repo filter, popup UI, repo grouping.** More
  informational density than their minimal core sidebar.

## Suggested order of attack

1. **Now** (small, live-impacting): the `install-wizard.sh` tmp+mv swap
   and the wait-reason clear on `error → running`.
2. **Next** (correctness under failure): don't-wipe-on-unknown process
   snapshot; atomic subagent-stop; spawn/remove off the UI thread; lsof
   fail-open.
3. **Strategic** (the moat): hooks-optional capture-pane detection, then
   wait-on-state scripting. Those two are what make "the best option for
   people who won't leave tmux" literally true, and both are feasible
   inside tmux.
4. **Polish:** README/AGENTS.md deploy-story alignment; shell-exit.sh
   guard; pkill -xf; tool_name sanitization; theme system; OSC
   notifications.

Before any commit: `cargo fmt` (per AGENTS.md), full `cargo test`, and copy
build artifacts into `~/.tmux/plugins/tmux-agent-sidebar/bin/` (plus
`agent-sidebar.conf` if hook registration or option defaults changed), then
toggle the sidebar off → on.
