# TODO panel: Google Tasks interactions + state chrome

> **For agentic workers:** this doc is written to be cranked through over
> multiple agent sessions on this branch. Work one phase per session, in
> order. Tick the checkboxes as you land work. Each phase is
> self-contained: it compiles, tests, and ships on its own. Before
> committing, run `cargo fmt` (hard rule, CI checks it), `cargo clippy`,
> and `cargo test`. UI changes need inline `insta::assert_snapshot!`
> tests — never substring assertions on rendered frames
> (see AGENTS.md, UI test rule). Run `cargo insta accept` only after
> eyeballing that the diff is intentional.

**Status:** not started. Exploration done 2026-11-12; decisions below are
settled.

**Origin:** follow-up to
docs/superpowers/specs/2026-10-31-todo-list-design.md (the original
implementation spec — read it first for storage/layout background).

**Goal:** bring the manual TODO panel to old-school Google Tasks
interaction patterns, and make its visual state (focused vs resting,
adding vs editing) legible at a glance.

## Settled decisions

1. **Completed items sink to the bottom under a divider** (the GTasks
   core model), replacing the hide-completed filter as the primary
   mental model. The shared tmux flag `@sidebar_todo_hide_completed`
   stays — it now means "collapse the completed section" — so the
   multi-sidebar sync plumbing is reused unchanged. H toggles it.
2. **Display order is derived, not stored.** visible_indices returns
   open items first, then completed ones. The file keeps insertion
   order; no format change.
3. **Accent discipline.** Accent means "focused affordance"
   (colors.rs docs say exactly this). At rest the panel renders in
   muted/inactive grays; accent appears only while Focus::Todos.
4. **Reorder via Ctrl-j / Ctrl-k** on the selected item, moving it
   within the open block. Unbound today (pane nav uses Ctrl-n/p).
   Keep index-based selection for now — the original spec's escape
   hatch (stable IDs) stays parked unless external-edit drift bites.
5. **Undo for destructive actions via the flash banner.** x/d/D stash
   the removed items and flash a banner naming u as the undo key.
   TodoState owns the stash and its deadline; the flash is just the
   visible affordance.
6. **Mouse hit targets split:** clicking the checkbox toggles;
   clicking the text selects (and edits if already selected+focused).
   GTasks click-the-text-to-edit convention, adapted to selection-based
   TUI navigation.
7. **Resting add affordance:** a muted "+ add" row at the panel bottom
   (clickable, via the existing todo_input_rect path) when the panel
   is focused or the list is empty.
8. **Dropped:** progress bar in the header. Due dates, notes, nesting,
   and multi-machine sync remain out of scope (original spec, unchanged).

## Invariants (must hold after every phase)

- With the panel hidden, every existing UI snapshot stays byte-identical
  (the original spec's success criterion — keep it).
- todos.txt format unchanged: parse and serialize round-trip. A
  hand-edited file keeps working. Never write anything but the
  canonical `[ ] ` / `[✓] ` prefixes.
- All mutations persist through crate::todo::update_in (locked
  read-modify-write); in-memory fallback + error surfacing on failure
  stays as-is.
- Selection stays an index into TodoState.items, always clamped to a
  visible item after any change (clamp_selection).
- The `q`, `c`, `w`, `?`, `t` globals keep working while the panel is
  focused; text-input keys (Ctrl-a/e/u/w, arrows) keep their meaning
  inside the add/edit buffers.

## Polish

Findings from the phase 2 review (commit 348cb09, 2026-11-12), the
phase 3 review (commit fd5ef5d, 2026-11-12), and the phase 4 review
(commit 76d8da5, 2026-11-12). Not a phase: sweep these in one pass
after the main bulk of development. None block anything; 1-3 are
render-side only, 4-7 are state/persistence-side. One phase 3 finding
was verified safe rather than fixed: crossterm parses raw-mode 0x0A
as Ctrl-j (Enter stays 0x0D), so reorder never collides with the
Enter toggle — pinned in a comment on the binding in src/app/input.rs.

- [x] 1. Add-mode hint threshold is non-monotonic at 24 columns
      (src/ui/panes/todo.rs). The hint fits when
      `width >= 3 + hint_width` (24: "+ ", cursor, one separator, hint)
      — but at exactly 24 the input budget is 0, `tail_fit` returns an
      empty string, and typed text is invisible behind the hint. At 23
      columns the hint drops and the input gets 20 columns instead, so
      one column wider renders strictly worse. Fix: show the hint only
      when the input keeps a usable minimum, e.g.
      `width >= 3 + MIN_INPUT_WIDTH + hint_width` with a floor of 4-8
      columns; snapshot the boundary widths when fixing.

- [x] 2. Editing a done item is an undefined visual state.
      begin_todo_edit (src/state/todo.rs) has no done-item guard, so
      once phase 1 lets j/k reach done items, `e` opens the editor on
      one and the accent wash renders over CROSSED_OUT text with a
      border-gray checkbox — a combination phase 2 neither defines nor
      forbids. Decide a policy: no-op `e` on done items (and carry the
      same rule into phase 5's click-to-edit), or accept the combination
      and pin it with a styled snapshot.

- [x] 3. Narrow help popups render rows with no description at all
      (src/ui/help.rs). The key column is sized from the widest key,
      which phase 3 grew from 11 (`PgUp / PgDn`) to 15
      (`Ctrl-j / Ctrl-k`) — so once the popup is clamped to a pane
      area under ~21 columns, the per-row action budget
      `inner_width - 1 - key_w - 2` computes to zero and every row
      renders as a bare key with a blank description (the 20-column
      snapshot shows `j / k` plus padding where `Mov…` used to be).
      Fix: cap key_w against the clamped inner width — leave a small
      action floor (4-8 columns) and truncate overlong keys via
      truncate_to_width — so descriptions keep a few columns. Note
      key_w currently also feeds the preferred popup width, so the
      cap must apply at render time after clamping, not to the
      preferred width. Snapshot the boundary widths when fixing.

- [x] 4. Undo after a failed-persistence delete duplicates items on
      disk (src/state/todo.rs). delete and clear_completed's Err
      paths remove the item(s) from memory only — the file keeps
      them and file_stamp is not refreshed — so the stash's stamp
      still matches self.file_stamp, undo's freshness check passes,
      and the restore goes through update_in, inserting a second
      copy of items the file never lost ([a,b,c] → [a,b,b,c]). The
      restore then clears self.error, erasing the only trace of the
      failed save. Fix: record in TodoUndo whether the removal
      actually landed on disk (a landed flag) and restore
      memory-only when it didn't. Test with a failing write.

- [x] 5. The undo freshness check races the refresh tick
      (src/state/todo.rs). undo compares the memory-cached
      self.file_stamp, stale by up to one refresh tick (~1s, per the
      refresh_if_changed comment): an external write inside that
      window passes the check and update_in restores over newer
      external state — what phase 4 task 3 set out to prevent.
      "Compare file_stamp captured at delete time" is satisfied to
      the letter; comparing against a fresh stamp_in at undo time
      (one stat per keypress) closes the race while staying simple.

- [x] 6. delete's early return skips clamp_selection
      (src/state/todo.rs). The pre-phase-4 code clamped
      unconditionally; the new let-else returns None before
      clamping on the concurrent-shrink path (another instance
      shrank the file) where self.items was just replaced by a
      shorter vec — selected can dangle out of bounds until some
      other mutation clamps (refresh_if_changed only clamps after a
      reload, which the just-refreshed stamp suppresses). No panic —
      toggle/set_text/move_item/begin_todo_edit all bounds-check —
      but navigation silently no-ops in the meantime. One-line fix:
      clamp before the early return.

- [x] 7. Two clippy warnings from the phase 4 commit
      (src/state/todo.rs): question_mark on delete's let-else and
      redundant_closure on undo's restore closure. CI passes (no
      -D warnings), but the pre-commit rule asks for a clean clippy
      and the rest of the lib is clean. Fix alongside 4-6.

## Redesign deviation (2026-11-12, later the same day)

The user asked for the Google Tasks flow verbatim, which supersedes
parts of the plan above:

- The completed-section divider row is gone from the panel (the header
  count and `?` carry that information). `H` still collapses/expands,
  but the completed section now starts expanded (`@sidebar_default_
  todo_hide_completed` default flipped to off) so a completed item
  sinks struck-through instead of vanishing.
- Enter edits the selected task (or starts a new one on an empty
  list); Enter again — in the editor or the add line — saves and
  lands on a fresh task; an empty Enter finishes entry. Esc backs out
  without creating anything. Space completes/uncompletes. The old
  Enter-toggle and Ctrl+Enter-complete ideas are dropped.
- Reorder gained Ctrl-↑/↓ aliases (Google's mapping, terminal-flavored)
  beside Ctrl-j/Ctrl-k; undo gained Ctrl-z beside `u`. Ctrl-z no
  longer falls through to group-collapse.
- The `?` popup is now a full-sidebar overlay: sections, wrapped
  descriptions with a hanging indent, and j/k + PgUp/PgDn scrolling —
  the old centered box truncated every description on the right.
- Subtasks/indentation are explicitly out of scope (user: "forget
  about indentation").
