## A. Event loop and state layer

### A1 — Render thread runs a full `ps` every 5s when the worker never armed the scan (MED, perf)

The background worker decides whether to ship a process snapshot with `process_snapshot_for_panes` (src/tmux/query.rs:845-852), which arms only for codex/opencode panes, shell-foreground panes, runtime-shim panes, or non-agent panes. It never checks `@pane_bg_cmd`, even though `bg_shell_cmd` is parsed from the same listing (src/tmux/query.rs:648).

Meanwhile the render thread's dead-bg-shell sweep (src/state/refresh.rs:985-995) fires whenever any pane has `bg_shell_cmd.is_some()`:

```rust
if process_snapshot.is_none() {
    *process_snapshot = ProcessSnapshot::scan();
}
```

Failure scenario: a window with only a Claude pane running a background shell and no other qualifying panes ships `process_snapshot: None` every tick, so every 5s the render thread blocks on a full-system `ps` — the exact stall the worker move was meant to remove. The freshly scanned snapshot is also local to `apply_snapshot`, so the port worker re-pays `ps` on its next run.

Fix: add a `@pane_bg_cmd`-presence check to `process_snapshot_for_panes` (the worker already holds the listing) so the sweep never falls back to the render thread.

### A2 — Failed lsof probe is conflated with a confirmed-empty port set (MED)

`apply_process_snapshot` (src/state/refresh.rs:783-788) treats the `_` arm uniformly: `None` (no entry) and `Some(vec![])` (probe ran, nothing listening) both advance `port_miss_streak`, and two consecutive misses (`REQUIRED_PORT_MISSES`) clear the badge.

But `run_lsof()` returning `None` — spawn error, 5s timeout SIGKILL, error exit — collapses into the same empty set (src/port.rs:211-219), and `PaneProcessSnapshot` carries no flag distinguishing "probe failed" from "no listeners". The comment at port.rs:202-215 acknowledges the distinction exists only in the debug trace.

Failure scenario: lsof exceeding its timeout twice in a row under load clears badges on live dev servers; commit 7ba7c68's hold only survives one failed sweep. The worker has the failure signal and throws it away.

Fix: add `lsof_ok: bool` (or `ports_confirmed: bool`) to `PaneProcessSnapshot` and skip streak advancement when the probe failed.

### A3 — Global single-letter toggles match regardless of modifiers; Ctrl-C toggles compact (LOW)

src/app/input.rs:264-267:

```rust
KeyCode::Char('c') => {
    state.global.toggle_compact();
}
```

No modifier guard — same for `w` (:267), `t` (:271), and the TODO-focus twins (:415-419). Other arms guard modifiers (`!ctrl` at :154, `KeyModifiers::NONE` for undo at :108), so this is an inconsistency. In raw mode Ctrl-C arrives as `Char('c') + CONTROL`: pressing the universal interrupt key flips compact mode and SIGUSR1-broadcasts to every other open sidebar; nothing in the TUI exits on Ctrl-C.

Fix: add an `if !ctrl` (or `KeyModifiers::NONE`) guard to the bare-letter toggle arms.

### A4 — `mark_window_finished_seen` leaves in-memory attention set (LOW)

On consumption it clears `runtime.window_finished` and unsets the tmux option (src/state/refresh.rs:209-217) but, unlike the agent path (`mark_focused_pane_seen`, refresh.rs:479-487), never clears `window.attention` in `other_windows`. For up to one snapshot round-trip, `row_collector` (src/ui/panes/row_collector.rs:181, 198) still renders the row as Done and `jump_to_next_attention` (src/state/layout.rs:423-427) can select the already-consumed row.

Fix: mirror the agent path — set the matching `OtherWindow.attention = None`.

### A5 — Window-pane port-scan targets built from the previous snapshot (LOW)

`apply_snapshot` calls `queue_port_scan_if_due(&sessions)` (src/state/refresh.rs:606) before `apply_session_snapshot` (:614) replaces `self.other_windows`, and the function reads `self.other_windows.values()` (:696-705) for `PaneKind::Window` targets. A just-appeared window pane is invisible to the scan for one 10s cycle; a just-died one gets a pointless target. The agent half of the same target list uses the fresh parse. Fix: pass the fresh `other_panes` already in hand.

### A6 — Every key event schedules a full frame render (LOW, perf)

The main `match key.code` ends with `_ => {}` and an unconditional `true` (src/app/input.rs:288-291); popup/search branches likewise return `true` for unmatched keys. Modifier-only presses and unbound keys force a full `render_frame` with zero state change. Fix: return `false` from inert arms.

### A7 — `jump_to_next_attention` agent half is O(rows x panes) (LOW, perf)

Inside the candidate loop, `self.pane_by_id(&target.pane_id)` (src/state/layout.rs:429-431) linearly scans every group/pane (src/state/focus.rs:65-74). The window-row half already got a lookup map (layout.rs:411-416); the agent-row half didn't. Fix: build one `HashMap` from `repo_groups` alongside the window map.

## B. UI rendering and input

### B1 — Popup stuck in "working" state swallows all keys (MED)

While a spawn or remove-confirm runs, input is fully swallowed (src/app/input.rs:55-57, :72-74):

```rust
if state.is_spawn_input_working() {
    return true;
}
```

The worktree spawn path probes `git::branch_exists` up to `MAX_COLLISION_ATTEMPTS` times (src/worktree/slug.rs), each bounded by the 5s `GIT_TIMEOUT` (src/git.rs) — on a hung repo (stale NFS, blocked `index.lock`, scenarios git.rs's own comment names) that is minutes of a modal that eats every key including `q` and `Esc`. Late results are already dropped safely when the popup moved on (src/state/popup.rs:1390-1404), so the lockout is the only hazard.

Fix: let Esc dismiss the popup while `working`; the late result is ignored by the sink.

### B2 — Flash banner paints over the bottom row while its click targets stay live (MED-LOW)

The banner renders at the last row after the todo panel and list (src/ui/panes.rs:638-656, `flash_y = area.y + area.height - 1`, `Clear` + background paint) and stays up ~4s (`take_flash`, src/state.rs). Click routing (src/state/layout.rs:762-810) still maps that row to the registered targets:

- With the TODO panel visible, clicking the banner text (which reads like a status line) toggles/selects the invisible item underneath.
- With the panel hidden, the banner row maps to the last agent line and calls `activate_selected_pane()` — an accidental pane jump to a row the user cannot see.

Fix: reserve the flash row in `PaneLayout` while a flash shows, or drop click targets whose row the banner covers.

### B3 — External todo reload leaves `editing.index` stale; commit overwrites another item's text (MED, data loss)

`refresh_if_changed` reloads `self.items` on any file-stamp change and never touches `self.todos.editing` (src/state/todo.rs:131-150). It runs on every refresh tick with no edit guard. `set_text` only bounds-checks the index (src/state/todo.rs:368-397) and writes whatever now sits there:

Scenario: two sidebars share the todo file. Instance B deletes an item above while instance A has index 5 open for edit. A's next tick reloads the shifted list; the edit buffer now visually sits on an unrelated item, and committing overwrites that item's text in the shared file. (`move_item`'s doc acknowledges selection drift as accepted; the edit-commit path silently destroys data instead.)

Fix: store the pre-edit text in `TodoEdit` and refuse the write in `set_text` when the item's current text no longer matches.

### B4 — Repo popup can be open-but-unrendered on tiny viewports (LOW)

`popup_height = ((inner_rows as u16) + 2).max(3).min(height_budget)` with `height_budget = area.height.saturating_sub(1)` (src/ui/panes.rs:446-453): on a <=3-row sidebar the early return fires, clearing `repo_area` to `None` while `popup` stays `Repo`. Input then consumes every key into invisible no-ops (src/app/input.rs:85-97); Enter still applies a filter change the user never saw. Mouse or Esc recovers. Fix: refuse to open the popup when the height cannot fit it.

### B5 — `pop_word_before` drains with the unclamped cursor as range end (LOW, latent)

src/state/todo.rs:647-651:

```rust
let cut = (*cursor).min(chars.len());
...
if cut < *cursor {
    chars.drain(cut..*cursor);
```

`cut` is clamped but the range end is not, so `drain` panics if the cursor ever exceeds the buffer length — contradicting the module contract ("clamped to the buffer's length before use"). All current mutators preserve the invariant, so this is latent — but B3's stale-buffer class is exactly what would trip it. Fix: clamp the range end.

### B6 — `query_matches` lowercases per field per row per frame (LOW, perf)

src/state/search.rs:31-37: `haystack.to_lowercase().contains(&query.to_lowercase())` — called 4x per agent pane, 5x per window row, per group, from `row_collector::collect` which rebuilds the whole list every frame. Dozens of avoidable allocations per pane per frame during an active search. Fix: lowercase the query once per `collect` (or cache it in `SearchState`).

## C. Hook pipeline and tmux integration

### C1 — Unquoted binary path in tmux shell-command position (MED)

tmux joins trailing args with spaces and runs them via `sh -c`. Three Rust-side sites pass `current_exe()` raw:

- src/cli/toggle.rs:191 — `split-window ... &self_bin` (trailing command position)
- src/cli/toggle.rs:1181 — `display-popup -E ... self_bin`
- src/cli/overview.rs:149, :182 — spawned overview command

A path containing a space (e.g. `~/Library/Application Support/...`, `~/Projects/My Tools/...`) makes `split-window` run `sh -c "/Users/u/Projects/My"` — the sidebar pane or popup fails with a shell error. A path containing `;`, `$()`, or backticks executes as a command. The conf-side registrations quote `#{@agent_sidebar_bin}` correctly (agent-sidebar.conf:206-227); only the Rust-side paths are unquoted.

Fix: `format!("'{}'", self_bin.replace('\'', "'\\''"))` at all three sites.

Resolution (fix pass): the man page splits the finding in two —
new-window/new-session/split-window/respawn-*/display-popup run a
single trailing positional via `sh -c`, but multiple trailing
positionals are exec'd directly without a shell (tmux 3.8). Verified
against a scoped server: an unquoted spaced path as the lone
`split-window` positional dies instantly; the same path as two
positionals (`prog arg`) runs. So the two toggle.rs sites (split-window
:191, `popup_command` :1181 — `self_bin` alone in command position) go
through the existing `crate::cli::setup::shell_quote`; the overview.rs
display-popup sites pass `[exe, "overview"]` and must stay unquoted
(quoting would corrupt argv[0]) — comments added on site.

### C2 — Hook hot path pays redundant tmux spawns (LOW, perf)

Per identity event, `@pane_subagents` is read twice (src/cli/hook/context/meta.rs:45 -> location.rs:421, then location.rs:154 inside `sync_pane_location`, which `set_agent_meta` calls), plus single-value spawns for `@pane_launch_cwd` (location.rs:89), `@pane_session_id` (location.rs:180), `@pane_status` + `@pane_wait_reason` in `handle_activity_log` (src/cli/hook/activity.rs:141, :158). `set_status` already unsets `@pane_attention` inside its batch (src/cli/mod.rs:96-103), yet activity.rs:202 and handlers/run.rs:129 unset it again. `on_user_prompt_submit` (handlers/run.rs:43-75) issues 5 separate spawns beside the already-batched prompt write. A UserPromptSubmit event costs ~13 tmux spawns where ~5 would do, each 1-3ms on the agent's hook budget.

Fix: one batched read (`display-message -t pane -p "#{@pane_subagents}|#{@pane_launch_cwd}|#{@pane_session_id}"`), reuse for the subagent guard, fold residual writes into the existing `apply_pane_options` batches.

### C3 — Five spawn sites bypass the documented IPC gate (LOW)

src/tmux/commands.rs:61-66 documents `exec_tmux` as the single choke point gated by `TMUX_IPC_ENABLED` (default off, so tests can never touch a live server). These spawn `tmux` directly, un-gated: src/app/workers.rs:328 (`capture_pane_tail` in the approval-scan worker), src/clipboard.rs:42, src/cli/overview.rs:143 and :176, src/cli/capture/tmux_probe.rs:51 and :73. Under `cargo test`, any of these paths reaching execution probes the user's live tmux server — exactly what the gate exists to prevent. Fix: route them through `run_tmux`/`run_tmux_capture`.

### C4 — `set_window_option` writes unsanitized values (LOW)

src/tmux/commands.rs:198-202 passes `value` through untouched, while every pane write sanitizes `\n` / `\r` / `|` (src/tmux/options.rs:341-346, reason documented: "the pane silently vanishes from the sidebar"). Spawn markers (repo path + branch) ride this path (src/worktree/flow.rs:93-106); a repo path containing a newline shifts `SpawnMarkers::parse`'s line order (src/worktree/markers.rs:49-63), so `remove_with` (flow.rs:218-247) would run `worktree_remove`/`branch_delete` against misparsed values. Fix: sanitize in `set_window_option` (or at the marker writes).

### C5 — CLI `spawn` nests worktrees when invoked from a spawned worktree (LOW)

src/cli/spawn.rs:23 resolves the repo with `git::repo_root` (`rev-parse --show-toplevel`, src/git.rs:52-54), which returns the worktree toplevel when the invoking pane sits in `/repo/.worktrees/feature` — the new worktree lands at `/repo/.worktrees/feature/.worktrees/<slug>`. The TUI popup path avoids this by resolving the main root via `--git-common-dir` (src/group.rs:241-247, pinned by the test at src/ui/panes/row_collector.rs:1369); the CLI path doesn't share that resolution. Fix: reuse the common-dir-based root resolution in `cmd_spawn`.

### C6 — Raw pane listing parsed five times per tick (LOW, perf)

`build_session_snapshot` (src/tmux/query.rs:194-226) runs `pane_output_needs_process_snapshot` + `pane_output_has_other_panes` (each a full `split_tmux_fields` pass over every line), then `extract_sidebar_window_info`, `collect_other_panes`, and `build_session_hierarchy` each re-split the same lines. 5x redundant string work per second on the render thread; the ps-scan decision can be derived from the already-parsed hierarchy in one pass.

### C7 — `notify_sidebars_of_pane` pays 2 spawns per event (LOW, perf)

src/cli/notify_focus.rs:7-27: `display-message` for the window id, then `list-panes -F #{@sidebar_pid}`, on every non-ActivityLog hook event — stacked on C2's budget. The window id could ride the batched read from C2.

## Appendix — fix plan (added 2026-11-19, same day as the audit)

### Strategy: one branch, not per-area worktrees

The initial instinct was one worktree per area (A, B, C) run in
parallel. Rejected: area boundaries do not match file boundaries, so
parallel lanes would still collide:

- src/app/input.rs — A3, A6 (area A) and B1, B4 (area B)
- src/state/layout.rs — A7 (area A) and B2 (area B)
- src/tmux/query.rs — A1 (area A) and C6 (area C)

An A/B/C split pays worktree-coordination cost without buying
isolation. Every fix here is small (a guard, a struct field, a few
lines), so they run sequentially in a single worktree (branch
`audit-fixes`, from `.opencode/worktrees/audit-fixes` off latest main),
one commit per finding or tight cluster — easier to review than three
merges, and nothing needs to land in parallel. If parallelism is ever
warranted, split by file cluster (todo/search, state/ports, input/UI,
hook/cli) and sequence the two cross-lane files inside one lane.

### Commit order

Follows "Suggested fix order" above with two adjustments: C3 (IPC gate
bypass) moves up into the small-guards batch — cheap, safety-adjacent,
and thematically next to C4/C5 — and the strays the list skips (A4, A5,
B4, B5) fold into their natural batches so none are dropped.

1. B3 — todo edit stale-index data loss: store the pre-edit text in
   `TodoEdit`, refuse the write in `set_text` on mismatch.
2. C1 — quote `current_exe()` at the three Rust-side spawn sites
   (toggle.rs x2, overview.rs x2).
3. A2 — add `lsof_ok` to `PaneProcessSnapshot`; failed probes skip
   miss-streak advancement.
4. A1 — arm `process_snapshot_for_panes` on `@pane_bg_cmd` presence so
   the render-thread fallback never fires for bg-shell panes.
5. B1 — Esc dismisses a `working` popup; B2 — reserve the flash row in
   `PaneLayout`. Both change rendered output → regenerate the affected
   inline snapshots (`cargo insta accept`) and review the diffs.
6. Small guards: A3 (modifier guard on bare-letter toggles), C4
   (sanitize in `set_window_option`), C5 (common-dir root resolution in
   `cmd_spawn`), C3 (route the un-gated spawns through
   `run_tmux`/`run_tmux_capture`), A4 (clear `OtherWindow.attention`
   alongside the tmux unset), A5 (pass the fresh `other_panes` to the
   port-scan queue), B4 (refuse to open the repo popup when it cannot
   fit), B5 (clamp the `drain` range end).
7. Perf batch: C2/C7 (batched reads), B6 (lowercase the query once),
   C6 (single-parse listing), A6 (`false` from inert key arms),
   A7 (HashMap for the agent-row jump half).

### Gates per commit

`cargo fmt` before every commit, then `cargo test` + `cargo clippy`;
`cargo fmt --check` must pass at the tip. Layout-affecting fixes (B1,
B2) also run `cargo insta accept` with the snapshot diffs reviewed.

### Deliverable

Branch `audit-fixes` pushed from the worktree and opened as a PR
against main. Deploy after merge per the standing procedure: release
build, copy `bin/tmux-agent-sidebar` into the plugin dir
(`agent-sidebar.conf` only if option defaults changed — not expected),
then toggle the sidebar off/on.
