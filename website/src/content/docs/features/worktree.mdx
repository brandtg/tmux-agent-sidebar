The sidebar can launch an agent in a new tmux window with one keystroke — either directly in the repo checkout or in a dedicated git worktree. Closing lets you pick the scope: tear down the window, worktree, and branch together, or keep the worktree/branch on disk and only close the window.

## Spawn modal

Opened with `n` or by clicking the `+` button next to a repo header.

| Key                                | Action                                                                                           |
| ---------------------------------- | ------------------------------------------------------------------------------------------------ |
| Text keys                          | Type the name (only when `MODE` is `worktree`; it names the branch and worktree — see below)     |
| `↑` / `↓` / `Tab` / `Shift+Tab`    | Move focus between `MODE` / `AGENT` / `NAME` fields                                              |
| `←` / `→`                          | Cycle the value when the mode or agent field has focus                                           |
| `Enter`                            | Create the window and launch the agent                                                           |
| `Esc` / click outside              | Cancel                                                                                           |

### Modes

The `MODE` field picks what the spawn creates:

- **`default`** — open a new tmux window directly in the repo checkout and launch the agent in it. No git side effects. The window is named after the agent, and the `NAME` field is not shown.
- **`worktree`** — create a git worktree + branch first, then launch the agent inside it.

### What gets created (worktree mode)

The modal's `NAME` field is slugified (lowercase, non-alphanumeric → `-`) and reused as:

- **Branch** — `<prefix><slug>`, where `<prefix>` defaults to `agent/` (e.g. `add login form` → `agent/add-login-form`). Colliding slugs get an incrementing suffix (`-2`, `-3`, …).
- **Worktree path** — `<repo>/.worktrees/<slug>` by default. Change the repo-relative directory with `@agent-sidebar-worktree-dir`; absolute paths and `..` are rejected.
- **tmux window** — the slug is used as the window name; the agent you picked in the modal (`claude` / `codex` / `opencode` / `antigravity`) launches inside it.

### Window layout

`@agent-sidebar-spawn-layout` picks how a freshly spawned (or resumed) agent window is laid out:

- **`full`** (default) — the agent takes the whole window; make your own splits as needed. Best for laptops.
- **`split`** — the agent gets a left one-third pane beside a blank shell (the sidebar pane sits on the far left). The original side-by-side layout.

Defaults for the agent, branch prefix, and worktree directory live in tmux options — see [tmux options](/tmux-agent-sidebar/reference/tmux-options/) for the full list.

## Close pane modal

Opened with `x` on a spawn-created pane, or by clicking the `×` button next to the branch name.

For a `worktree` spawn:

| Key             | Action                                                                                                                                 |
| --------------- | -------------------------------------------------------------------------------------------------------------------------------------- |
| `y` / `Enter`   | Close the tmux window, remove the git worktree (`--force`), **and** delete the branch the spawn created (`git branch -D`)             |
| `c`             | Close the tmux window only, keep the worktree and branch on disk                                                                       |
| `n` / `Esc`     | Cancel                                                                                                                                 |

For a `default` spawn there is no worktree or branch, so the dialog offers only `[y] close window` and `[n] cancel`.

### Why `-D` and not `-d`?

Spawn-created branches are auto-generated under the `agent/` prefix for short-lived explorations, and the close modal opts into `git branch -D` so it works even when the branch has not been merged upstream. Recover via `git reflog` if you delete one by mistake.

## Availability

The plugin no longer registers Claude Code's `WorktreeCreate` / `WorktreeRemove` hooks: Claude Code treats them as delegation hooks that must perform the worktree operation and return its path, so observe-only registrations break Claude Code's built-in worktree isolation. The sidebar still tracks worktrees it spawns itself and follows agent location changes via `CwdChanged`.
