The sidebar renders one row per agent pane across all tmux sessions and windows. Each row is packed with live metadata pulled from the agent's hooks and from tmux itself.

## Chyron (header overlay)

The single header row is an event channel that shares space with the
toolbar: when an agent's state changes in a way that wants your eye,
the row names the event for a moment, then hands the row back.

- `✓ <agent> done` — a turn finished and you have not looked at it yet
  (green)
- `◐ <agent> waiting` — a hook wants you: permission prompt, question
  (amber)
- `✕ <agent> failed` — the pane transitioned to error (red)

Each event reads in beats: a short bright flash (the eye-catcher —
colored text only, never a background block), then ~3 s of colored
text in the same hue so the name is actually readable, then a short
fade and the toolbar returns. A banner wider than the row becomes a
ticker: it holds the opening words for a moment, scrolls horizontally
at a slow, readable pace until the tail has been visible, pauses, and
only then fades — the scroll always completes before the close.
Focusing the pane the event has fired for ends the display
immediately — nothing lingers over output you already read. Opening the `/` search or the menu dismisses the event
outright. Clicking the banner selects that agent's row and scrolls it
into view (the menu button in the corner keeps working throughout). A
sidebar that opens mid-session shows nothing until its first event,
and a restart never replays old flags.

### Menu (repo filter + notices)

The header's right edge is one button: `— ▾` normally, `ⓘ ▾` when a
notice exists (top-right, where alerts live). Opening it with `r` or a
click drops a menu with the notices sections — new version,
`Plugin / claude`, missing hooks with per-agent `[copy]` / `[prompt]`
buttons — above a `Repos` section listing the repo filter. With no
notice, the menu is just the repo list. `j` / `k` and `Enter` navigate
the repo list; the notice rows are click-to-copy.

### Search

Press `/` to type a query flush left in the header. The list narrows in
place while the repo groups stay intact. Matching is case-insensitive across the
agent session title, tmux session name, and git branch; a query that matches a
repo or session name keeps that whole group visible. `Enter` keeps the query
applied, `Esc` clears it, `Ctrl-u` clears the text without closing the input,
and `Ctrl-w` deletes the word before the cursor. Jumping to a pane clears the
query, so leaving the sidebar always returns the list to its unfiltered state.

### Navigation and grouping

`a` cycles to the next row that needs attention, `g` / `G` jump to the top and
bottom, and `[` / `]` jump between group headers. `z` collapses the selected
group to a single header line (its waiting / error segments collapse into the
badge) and `Z` expands every collapsed group. `s` toggles grouping between
repository and tmux session; the choice is written to `@sidebar_group_by` and
shared by every open sidebar.

## Row elements

### Status icon

- `●` running
- `◎` background shell running
- `◐` waiting
- `○` idle
- `✕` error

When multiple signals compete on the same pane, the sidebar resolves them in this order:

**`running` > `permission` > `background` > `waiting` > `idle`**

- **running** always wins while the agent is actively using tools — it overrides any background shell or waiting notification for the duration of the tool call.
- **permission** (a `permission_prompt`, `permission_denied`, or `elicitation_dialog` wait reason) overrides a live background shell. You still have to act on the prompt, so the row stays in `waiting` instead of being hidden behind `◎`.
- **background** wins over softer waits. When a background shell is live and the agent pauses for something informational — `auth_success`, `rate_limit`, `session_resumed`, `teammate_idle`, etc. — the row stays on `◎` instead of flipping to `◐`.
- **waiting** covers everything else the agent has chosen to surface.
- **idle** is the fallback when nothing else applies.

### Permission badge

Only safety-relevant deviations get a badge; the auto-accept family is the everyday steady state and stays unbadged:

- `plan` — plan mode
- `!` — bypass permissions (dangerous)

The underlying mode is still tracked per pane (`@pane_permission_mode`), so the badge can return without config changes if the badge policy is widened.

### Session name

Defaults to the agent name. Can be changed through Claude Code's `/rename`. OpenCode and Hermes session titles are picked up automatically (Hermes titles are read from its `~/.hermes/state.db` session store).

### `+` marker

Indicates the pane sits in a git worktree (any worktree, not only sidebar-created ones). Sidebar-spawned worktrees additionally show a `×` button for one-keystroke teardown. See [Worktree](/tmux-agent-sidebar/features/worktree/) for details.

### Branch

Current Git branch for the pane's cwd. Claude updates dynamically through the `CwdChanged` hook.

### Elapsed time

Time since the last user prompt.

### Task progress

Synchronized from the agent's task list. Each task gets a glyph for its state; the trailing count is `completed/total`.

- `✔` — completed
- `◼` — in progress
- `◻` — pending

```text
  ✔✔◼◻ 2/4
```

### Background shell

Shown when an agent explicitly starts a Bash tool in the background, such as a long-running `npm run dev` or watch command. The sidebar moves that pane from `running` to `background` only when the hook payload includes a background flag (`run_in_background` / `runInBackground`); command text alone is not guessed.

The row body surfaces the actual command so you can tell at a glance what is running, and keeps it visible even when the agent briefly flips back to `running` for another tool call. Only the most recent background Bash is tracked; if the agent launches a second one, it overwrites the first in the row. The marker clears automatically when the process exits (via a `ps` liveness sweep each refresh tick).

```text
  npm run dev
```

If the hook payload omitted the command string for some reason, the row shows a `(background shell)` placeholder so the status transition is still visible.

Once the underlying process exits, the sidebar's next refresh tick (about once a second) scans `ps` for the stored command, clears the row, and downgrades the pane from `background` to `idle`. The `(background shell)` placeholder is exempt from the sweep — without a real command we cannot verify liveness, so it persists until SessionEnd.

### Subagent tree

Parent-child branches for spawned sub-agents. Middle entries use `├`, the last uses `└`. Each row shows the subagent kind followed by `#<id>`.

```text
├ Explore #a1b2
├ Plan    #d4e5
└ Bash    #dead
```

### Listening ports

Localhost ports the pane's process is listening on.

### Response preview

Preview of the latest agent response.

### Prompt text

Latest user prompt.

### Wait reason

Why the agent is waiting — populated from Claude's `Notification`, `PermissionDenied`, and `TeammateIdle` hooks.
