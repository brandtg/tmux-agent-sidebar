Every agent row carries its own git context, resolved by a background worker so the render thread never spawns git.

## Rows

Each agent row shows:

- **Branch** — the branch checked out in the pane's working directory; worktrees render as `+ <name>: <branch>`
- **Ahead / behind** — `↑N` / `↓N` counts vs. the configured upstream
- **Dirty count** — `~N` uncommitted paths (staged + unstaged + untracked) from `git status --porcelain`
- **Ports** — listening dev-server ports detected in the pane's process tree

The movement and dirty cluster renders only what exists: a clean, synced branch shows no right-side cluster at all, and short sidebars truncate the branch text before sacrificing it.

## Repo groups

Panes are grouped by git repo root (or launch directory when no repo resolves), with one header per group. Worktrees group under their original repository. The grouping mode is configurable with `@sidebar_group_by` (`repo` or `session`).

## Data source

Everything comes from the sidebar's background git-info resolver, TTL-gated per path. Detailed staging work (add, commit, diff) happens in the agent pane itself, where `git` already runs.
